# client_react → client_nextjs conversion (Next.js App Router)

Source of truth: `../client_react/` (Vite + React 18 + react-router-dom v6 + MUI v5 + zustand + react-query v4 + yup + socket.io-client). Target: `client_nextjs/` with Next.js 15 (App Router), TypeScript strict, same Mongo API contract to `../server_fastapi/`.

Agent rules: `AGENTS.md` in `../server_fastapi/` applies (lint/type/test before marking done). Layout: `app/` (App Router), `src/lib/`, `src/store/`, `src/services/`, `src/components/`, `tests/`.

## Inspection findings (used to define tasks)
- Routing (`src/App.tsx`): 15 named routes (`/`, `/my-matches`, `/matches`, `/messages`, `/my-account/*`, `/dashboard/*`, `my-properties`, `/agreement`, `/agreement/:id`, `/policy-agreement`, `/components`, `/activate-account/:token`, `/google/redirect`, `/twitter/redirect`, `*` 404). Guard: inline `userStore.auth ? protected : <Home/>` (not redirect). Auth persistence: `zustand persist('userStore')` (localStorage) with `access_token` + `refresh_token` + computed `expirationTime`/`refreshExpirationTime` + decoded JWT `userDetails` + `rules`. SessionMaintainer (`src/pages/Login/SessionMaintainer.tsx`) does timer-based refresh (`5 s` before `expirationTime`) + `GET /api/account/me` liveness check.
- State stores (`globalState/`): `useUserStore` (persist), `useProfileStore` (persist + devtools), `useCriteriaStore` (persist), `useNotificationsStore` (transient), `useCriteriaWithoutAccountStore` (persist), `useGlobalSetCriteria` (no persist), `useBackdropStore`/`useScrollLockStore` (no persist). All use raw `zustand` `set` with no dedicated actions.
- React-query (`src/index.tsx`): default `new QueryClient()` (no custom `staleTime`). 12 `useQuery` hooks (property-details `['property-details']`, matched-properties `['matched-properties', params]`, matched-tenants `['matched-tenants', params]`, number `['number']`, suggested-properties `['suggested-properties']`, suggested-properties-without-account `['suggested-properties-without-account']`, suggested-tenants `['suggested-tenants', Object.values(params)]`, messages `['messages', filterByProperty]`, properties `['properties', activeTab]`, offer `['offer', ...]`, get-envelopes `['get-envelopes', ...]`, tenantMatch `['tenantMatch', ...]`). 9 `useMutation` patterns (like/unlike/cancel/dislike + offer create/cancel/accept/refuse + account mutations + id-card). No `invalidateQueries` / `setQueryData`; freshness is `.refetch()` in `onSuccess`.
- API layer (`src/utils/axios.ts`): `axiosWithToken(token)` factory creates instance per call (`timeout:30000`, `baseURL=config.apiUrl`, `Authorization: Bearer <token>`, `Content-Type:application/json`). **No interceptors**. All endpoints listed in the state/data-layer report (§3); 100% parity required.
- Validation (`yup` via `@hookform/resolvers/yup`): login schema (`email`, `password.min(6).max(32)`); create-account (`first/last` + `email` + `password` with uppercase/digit/symbol custom test + `min(8).max(32)`); forgot (`email`); reset (`password` = `strongPasswordValidator` from `src/utils/validation.helper.ts` + `repeat-password.oneOf`); criteria form (`criteriaFormSchema` in `src/pages/SetCriteria/criteria.contants.ts`: 16 boolean-flag groups + 5 number-range arrays + 9 enum fields + `areaOfInterest` required + location lat/long); account details (`userSchema`); notifications (`userNotificationSchema`, 5 booleans). All forms: `react-hook-form`, `mode: 'all'`.
- Theme (`src/theme.ts`): MUI `createTheme` with overridden breakpoints (`mobile`, `tablet`, `laptop`, `desktop` registered via module augmentation). Default palette (no override) + default typography (font `At Gambit` applied ad-hoc in styled components, not in theme).
- Socket.IO (`context/SocketContext.tsx` + `App.tsx`): connects only when `userStore.auth` truthy, `io(config.apiUrl, { auth: { token: access_token }, transports: ['websocket'] })` (dev allows polling). Events emitted/listened: none in inspected files (chat messages delivered via REST `GET /api/chat/:id` + manual refresh; socket only provides `users` registry).
- Social auth: Google (`LoginSocialGoogle`), Facebook (`LoginSocialFacebook`), Twitter (full redirect + `oauth2_token` cookie). Twitter redirect (`/twitter/redirect`) reads cookie via `react-cookie`, decodes JWT, removes cookie, navigates `/`.
- Agent routes (`AgentDashboard/MyDashboard.tsx` nested routes): `/` (AgentDashboard), `/contracts` (Agreement list), `/contracts/:id` (AgreementDetails), `/agent-property` (AllProperties), `/agent-matches` (Matches), `/my-account/*` (MyAccount). Uses `useLogs` hook calling `GET /api/admin/*-log/{id}`.
- Key pages missing from source inventory (need manual mapping): `PagesComponents/AreaOfInterest` (map geocode by text), `PagesComponents/HeaderLoggedIn` (layout header + account widget popover with logout/change-password), `PagesComponents/PropertyMatch` (property card), `PagesComponents/YourProperty` (owner property view), `PagesComponents/ImproveTrustScoreModal`, `PagesComponents/ValpalSection`, `PagesComponents/DailyNews`. `Messages/` has nested routes not fully mapped (conversation + document upload + signed docs + offer reviews).

## Key flows discovered (reference only — do not delete)
- Auth: `register → verify email → invitation → login (JWT pair) → session maintainer (timer refresh + me check) → refresh rotation → logout (revoke both tokens)`. Twitter redirect relies on cookie `oauth2_token`; Google redirect uses popup `postMessage`.
- Property lifecycle: `draft` (`POST /api/asset/draft`) → `publish` (`POST /api/asset` or `PATCH /api/asset/{id}`) → `rented` (manual status change, not endpoint). Images: `upload` (multipart) → `generate-images` (WS prompt).
- Criteria lifecycle: anonymous criteria (`useCriteriaWithoutAccountStore`, `POST /api/suggestion/without-account/properties`) → account creation (`POST /api/account/register` + initial setup wizard) → account criteria (`PATCH /api/criteria` or `POST /api/criteria`). Role flip: `NewUser` → `Tenant`/`Landlord` after setup.
- Matching lifecycle: `suggestion` (`GET /api/suggestion/*` with filters) → `like` (`POST /api/match/properties`/`tenants`) → `mutual` (`chosen:true` on both sides) → `chat` (`POST /api/chat/create` or find via `GET /api/chat/matches/{matchId}`) → `offer` (`POST /api/offer`) → `document approval` (`PATCH /api/document/{id}`) → `DocuSign` (`POST /api/docusign/create-envelope`) → `signed` (`GET /api/docusign/envelope/{id}/download`). Unmatch (`PATCH /api/match/{id}/unmatched`) deletes chat association implicitly.
- Admin: `Agent` role sees `/dashboard/*` routes (`AgentDashboard`). Admin log explorer (`useLogs`) uses `GET /api/admin/*-log/{id}` with pagination/search.
- Notifications: `GET /api/notification/unread` returns `{ unread }`; viewing a notification (`GET /api/notification/{id}`) returns body + updates `viewed` state. Unread count surfaces through `notificationsStore.unreadMessages`.
